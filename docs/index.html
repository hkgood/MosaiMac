128 KB 内存，和一套窗口系统。

1984 年的 Macintosh 在 7.836 MHz 的 68000 上跑着可拖动窗口、区域裁剪、脏矩形重绘、滚动条和下拉菜单。它的核心就是 BitBlt 和 Region。

480×320，不缩放

512×342 → 480×480 本来需要一整个重采样阶段。但 480/320 = 1.5，512/342 ≈ 1.497，宽高比本来就是一致的。直接用原生尺寸，等于删掉了一次全像素遍历。

Span list，不是 packed RLE

原版把 Region 塞进 16 字节，每个集合运算都是手写位运算。S31 有 16 MB PSRAM，用内存换可验证性是白赚的。矩形 Region 仍然原地存储、零堆分配。

1-bit 才是重点

在没有 GPU、没有 DMA 引擎、没有 alpha 的设备上，1-bit 是唯一一种能让整屏重绘塞进 16 ms 的位深。480×320 是 18,750 字节，不是 460 KB。

决定一切的那一条。

窗口移动损伤的是新旧位置的对称差。你怎么存这个数，帧率差一个数量级。

14× → 6.7×

非对齐 BitBlt 曾经走逐字节分块路径，比对齐慢 14 倍。拖窗口天生非对齐，所以改成把源数据过 64 位窗口滑动。

0.104 → 0.047 ms

O(y) → O(1)

qd_region_spans() 每次查询都要把前面所有行的 span 数累加一遍，让整屏 region blit 变成平方复杂度。换成前缀和 offset 表。

0.040 → 0.014 ms

引擎踩过的坑。

每一条在常见路径上都看不出来。现在每一条都有回归测试守着。

  • Missing phase shift in rop_byte_chunk()只在 dp == 0 时正确，也就是所有非对齐 span 全错。整字节路径把它盖住了。
  • Phase-blind partial-byte mask in qd_fill_span_1bpp()只在 head/tail 被裁剪时错，第一次暴露是 frameRect 把 3px 边框裁成 3px。
  • XOR truncated to the operand intersection只有 INTERSECT 会被交集框住，XOR 和 UNION 都会伸出去。
  • spans_xor lost spans一个 span 可能压住另一个列表的下一个 span，头尾合并和双游标都处理不了。换成事件扫描。
  • qd_port_set_white() existed, qd_fill_rect() ignored it调用方设白笔期待擦除，实际得到黑色，而且完全没法察觉。
  • The empty region was a sentinel pointer忘初始化会变成堆损坏，而不是一个空 region。
